## Duplicate clusters (need merging)

### 1. Homepage / site content editing — FOUR ways to do the same thing
- `/admin/content` — legacy CMS-ish editor for `site_content`, `site_config`, `feature_flags`, `notification_templates`, `broadcasts`
- `/admin/content-editor` — newer schema-driven live preview editor (writes `site_config` draft/published keys)
- `/admin/settings/homepage-sections` — `site_config` editor for homepage sections
- `/admin/settings/homepage-images` — `site_config` editor for homepage images
- **Recommend:** consolidate to **`/admin/content-editor`** only. Delete `/admin/content`. Fold the homepage-sections/homepage-images JSON blobs into `content-editor` schemas. Branding/contact-info/navigation already redirect into `/admin/content` and should just become tabs inside `content-editor`.

### 2. Inbox / messaging / notifications / contacts — FOUR overlapping inboxes
- `/admin/inbox` — full unified inbox (conversations + messages + contact_submissions) — most fleshed out
- `/admin/inbox/pipeline` — kanban view of the SAME `conversations` table
- `/admin/contacts` — CRM view of the same conversations as a contact list
- `/admin/messaging` — sms_messages / whatsapp_messages / ussd_sessions log
- `/admin/messaging/templates` — `message_templates`
- `/admin/messaging/campaigns` — `message_campaigns` / `broadcasts` / `notification_queue`
- `/admin/notifications` — `broadcasts` / `notification_templates` / `notifications` (in-app)
- `/admin/automations` — `automation_rules` (rule engine that ties triggers to messaging actions)
- **Recommend:** make **Inbox** the primary single page (with sub-tabs: All / Pipeline / Contacts). Keep **Templates**, **Campaigns**, **Automations** as siblings under Marketing. **Delete** `/admin/notifications` (fold its broadcasts/templates into Campaigns and its in-app notifications into Inbox). **Delete** `/admin/inbox/pipeline` as a route — make it a view-mode toggle on `/admin/inbox`. **Delete** `/admin/contacts` as a route — make it a view-mode toggle on `/admin/inbox`.

### 3. Investors — split across People & Finance, FOUR pages
- `/admin/investor-relations` — investor_interests pipeline (currently labeled "Investors" in People group)
- `/admin/investor-relations/opportunities` — investment_opportunities CRUD
- `/admin/investors` — investor_profiles list ("All Investors" in Finance)
- `/admin/investments` — investments + investment_opportunities ("Total Investments" in Finance)
- `/admin/settings/fund-documents` — investor_documents
- **Recommend:** merge into ONE **`/admin/investors`** page in People with sub-tabs: Profiles / Pipeline / Opportunities / Investments / Documents. Delete the other three routes (or have them redirect).

### 4. Suppliers / Partners / Sponsorships
- `/admin/suppliers` — products + orders (this is currently SUPPLIER products/orders, NOT supplier records)
- `/admin/suppliers/[id]`, `/admin/suppliers/[id]/edit`, `/admin/suppliers/new` — supplier record CRUD
- `/admin/suppliers/sponsorships` — supplier_directory
- `/admin/partners` — managed_partners
- `/admin/partnerships` — managed_partners (SAME table)
- `/admin/sponsor` — sponsorships + farmer_public_profiles (sponsor-a-farmer program — different concept)
- `/admin/sponsor-tiers` — sponsor_tiers (config for sponsor program)
- **Recommend:** Per project memory, partners ARE suppliers. **Merge** `/admin/partners` and `/admin/partnerships` INTO `/admin/suppliers` as a "type" filter. Keep `/admin/suppliers` as the canonical list (rename current orders/products view to `/admin/suppliers/marketplace`). Keep sponsor-a-farmer as a separate concept under Marketing (sponsor + sponsor-tiers).

### 5. Insurance
- `/admin/insurance` — claims + policies + products + members
- `/admin/insurance/products` — insurance_products CRUD
- `/admin/insurance/parametric` — parametric_products / parametric_policies
- `/admin/settings/insurance-pricing` — site_config "insurance_pricing"
- **Recommend:** Merge to **`/admin/insurance`** with tabs: Policies / Claims / Products / Parametric / Pricing. Delete the other three routes.

### 6. Carbon (currently 4 demo-data pages)
- `/admin/carbon`, `/admin/carbon/projects`, `/admin/carbon/credits`, `/admin/carbon/verifications`
- All four are largely empty/demo data shells.
- **Recommend:** Collapse to a single `/admin/carbon` with internal tabs.

### 7. Financial dashboards (one main + two sub-tables)
- `/admin/financial`, `/admin/financial/collections`, `/admin/financial/disbursements`, `/admin/loans`, `/admin/payments`, `/admin/banking`, `/admin/wallet`
- All read overlapping `loans` / `payments` data.
- **Recommend:** keep `/admin/financial` as the dashboard, keep `/admin/loans` (single source for loan management — collections/disbursements become tabs inside it), keep `/admin/payments` and `/admin/wallet` distinct, **delete** `/admin/banking` (overlaps wallet+ledger and is mostly demo data).

### 8. Settings duplicates within itself (literal duplicate links in sidebar)
- `Homepage Sections`, `Homepage Images`, `Videos`, `Ad Packages`, `Impact Metrics`, `Fund Documents` are listed in BOTH the `Content` and `Settings` groups in `layout.tsx`. They render the same component each time.
- **Recommend:** keep the link in the new Content group only.

### 9. Members vs Farmers vs People
- `/admin/members` — `profiles` table list
- `/admin/farmers` — bulk import + list of farmer-role profiles + plot data
- `/admin/applications` — `membership_applications` (incoming join requests)
- `/admin/kyc` — `kyc_documents` / `kyc_verifications`
- `/admin/credit-scores` — `profiles` (calculated score column)
- `/admin/compliance` — `compliance_issues` + `kyc_documents` + `profiles`
- **Recommend:** Keep `/admin/members` as canonical. Move farmer bulk import into `/admin/members?action=import` modal. Keep `/admin/applications`, `/admin/kyc`, `/admin/compliance` distinct. Delete `/admin/farmers` as a separate route (keep import flow). Keep `/admin/credit-scores` (it's a different lens but currently sparse — flag for REWIRE).

### 10. Trading / Exchange / Marketplace
- `/admin/trading` — trade_orders / commodity_prices / trade_quotes (real)
- `/admin/exchange` — exchange_listings (member-to-member barter, real but small)
- `/admin/suppliers` (current) — products + orders (the marketplace)
- **Recommend:** keep all three but rename the supplier-products page to `/admin/marketplace`. Group them under Operations.

### Pages with mismatched titles vs folder
- **/admin/investor-relations** is labeled "Investors" in the sidebar (the People group entry), while the literal folder `/admin/investors` is labeled "All Investors" (in the Finance group). Confusing.
- **/admin/suppliers** at root shows products + orders (a marketplace view), not supplier records. The supplier record CRUD lives at `/admin/suppliers/[id]`, `/admin/suppliers/new`, `/admin/suppliers/sponsorships` — all of which call the actual `suppliers` table. The list page should be renamed.
- **/admin/farmers** title is "Bulk Import Farmers" in practice — the URL implies a farmers list.
- **/admin/sponsor** vs **/admin/sponsor-tiers** — singular "sponsor" page is the sponsor-a-farmer program, not a settings page.
- **/admin/farm-overview** has its own KPI dashboard but a "Farm Overview" title — overlaps Dashboard naming.
